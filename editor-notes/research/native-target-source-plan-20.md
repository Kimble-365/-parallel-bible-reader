# Native 2.0 target notices and corresponding source plan

This plan uses the exact Cargo.lock and the explicit default-plus-custom-protocol feature set. The dedicated read-only workflow measures normal dependency edges and normal+build edges for Windows x64, Apple Silicon, Intel Mac, Android ARM64 and ARM64 iOS simulator. No dev edges are included. Original raw graph outputs, package/version/archive identities, warning cases, MPL cases and the 36 reviewed notice cases are retained in TARGET-RIGHTS.json and checksum-addressed raw graph files.

These are conservative reachability graphs, not a binary inclusion analysis. Normal graphs can include procedural macros. “Build graph only” means only reachable when build edges are included; generated code and data can still enter a distribution. Absence only applies to the measured target/features; it does not dismiss an advisory or licence for all other configurations. A failed command, malformed graph or unknown package must fail the measurement, never become an empty/absent result.

## Candidate preparation requirements

1. Pin the candidate code, lock, target/features and actual artifact digests. Compare actual shipped files and linked/code-generated components with these graphs. Existing unsigned desktop/debug APK/simulator artifacts are review packages, not public releases or physical iPad builds.
2. Keep the exact source archive URL/checksum for each relevant dependency. Preserve archived notices and applicable pinned upstream texts, including the 36-case evidence register. Retain declared alternatives verbatim until an applicable choice is reviewed; do not invent copyright holders.
3. For MPL-2.0 components that enter the distribution, identify the covered files, any modifications and corresponding source. Prepare a persistent source distribution or appropriate availability mechanism with the required notices and licence copy. A bare upstream URL or the graph alone is not treated as completing these obligations. Original locked crate archives, their hashes and project modifications form the evidence base.
4. For permissive components, include applicable full licence/attribution and notice material in a durable, readable product bundle. Check generated/native components independently. The existing audit sidecars are not automatically product notices.
5. Resolve the objc2/Apple SDK guidance, missing source provenance/redirect cases and any applicable system/SDK/installer obligations against the actual distribution. Rust/Cargo/npm build tools, platform SDKs, webview runtimes, bundled fonts and per-edition Scripture terms are distinct inventories, not inferred from Cargo alone.
6. Recheck source/notice inclusion in each actual installer/app/APK/simulator package and expose the material locally. Retain source identities and test output. No public deployment, signing, permissions change or formal release approval follows from this plan.

The next concrete implementation is a candidate notice/source bundle backed by the measured target evidence and actual shipped-file assessment. Native GUI/clipboard/export/share and physical-device/phone usability still require execution checks. Six audit warnings remain recorded and unsuppressed; measured target absence can scope follow-up but does not erase the lockfile warning. No Scripture corpus or user store is read or modified by the graph tool.
