# Native dependency source review sidecar

The source review ZIP contains every original external Cargo.lock crate archive verbatim, conservatively including target-specific/build-only crates; archived notice texts; the 36-case pinned upstream evidence register and exact snapshots; target graphs with source archive identities; selected native host source/configuration and the project licence. Every included file has a byte count and SHA-256 in BUNDLE-MANIFEST.json. Fixed ZIP timestamps, sorted members, fixed permissions and stored compression make repeated outputs byte-identical.

The builder independently matches the complete external lock set, lock/source identities, each original cache archive checksum and target graph identity. It reruns pinned-review verification before copying any evidence. A second pass opens the actual ZIP and rejects missing/extra/duplicate/unsafe members, changed bytes and clearance flags. The dedicated read-only CI job repeats the source bundle twice and compares the actual ZIP bytes, retaining a separately identified review artifact. Seven fixture checks cover unchanged CRLF/Unicode notice bytes, repeatability, corruption, extra members, unsafe names, false clearance and altered/stale source identities.

Reproduce after the locked archive/notice and target graph audits with `python tools/local/package_native_rights_20.py --audit AUDIT_DIR --cache CARGO_REGISTRY_CACHE --source-commit COMMIT --out OUTPUT.zip`. Keep the original locked archives intact; do not treat extracted/rewritten files as equivalent sources. These source archives make actual dependency source available for review rather than just listing upstream download URLs.

This is a dependency-source review sidecar, not a complete buildable application, SDK/font/Scripture source distribution, product notice integration, signed installer or public release. It deliberately preserves all original notice gaps and upstream SDK/licence-choice questions. Source availability for an actual authorized distribution must be durable and applicable to the actual covered files, modifications and shipped/generated components. A 30-day CI artifact alone does not establish that. No licensing alternative or copyright holder is invented.

Actual installer/app/APK/simulator contents, linked/generated components and platform/SDK obligations still require assessment against this conservative evidence. Embed or accompany a reviewed, locally accessible notice/source bundle as applicable only after those checks. Native GUI, export/share/clipboard and physical-device/phone usability remain separate incomplete tests. No merge, deployment, signing, access change or public-release approval follows from this artifact.
